# ADO-01 / ADO-04 — การควบคุมช่องบังคับตอนสร้างเคส

เป้าหมาย: สร้างเคสได้ภายใน 30 วินาที (G-02, CAP-01) จึงบังคับกรอกตอนสร้างเพียง 3 ช่อง
ข้อมูลอื่นทั้งหมด (หมวดหมู่ สาเหตุ วิธีแก้ ผลิตภัณฑ์) ไปบังคับตอนปิดเคสแทน (หลักการ D-01)

## ช่องบังคับปัจจุบัน
| ช่อง | เหตุผล |
|---|---|
| ลูกค้า / ผู้แจ้ง | รู้ว่าเคสของใคร และใช้แสดงเคสเปิดของลูกค้ารายเดิม (CAP-11) |
| หัวข้อ | ใช้ค้นหาเคสคล้าย (SIM) และแสดงในคิว |
| ช่องทาง | นับภาระงานตามช่องทาง (KPI-17) |

## สิ่งที่บังคับในระดับระบบ
- Backend สร้างสถานะ NEW เมื่อมีครบ 3 ช่องนี้เท่านั้น ขาดช่องใดเป็น DRAFT (BR-02)
- รายชื่อช่องอยู่ที่ `REQUIRED_CAPTURE_FIELDS` ใน `backend/app/api/v1/endpoints/adoption.py`
- เทสต์ `backend/tests/test_adoption.py` จะล้มทันทีถ้ามีการเพิ่มช่องบังคับที่ 4 โดยไม่แก้รายการและเทสต์อย่างตั้งใจ
- หน้า "เวลาที่ใช้สร้างเคส" วัดเวลาจริงทุกเคส ใช้ตรวจว่าการเปลี่ยนแปลงทำให้ช้าลงหรือไม่

## ขั้นตอนอนุมัติก่อนเพิ่มช่องบังคับ
1. ผู้เสนอเขียนคำขอ: ช่องที่ต้องการ, ใครใช้ข้อมูลนี้ และใช้ทำอะไร (หลักการ D-02: ช่องบังคับต้องให้ประโยชน์กลับมาที่ผู้กรอก)
2. ทีมพัฒนาประเมินว่าเติมทีหลังหรือบังคับตอนปิดเคสแทนได้หรือไม่ ถ้าได้ ให้ใช้ทางนั้น
3. ทดลองกับผู้ใช้อย่างน้อย 3 คน ดูค่ากลางเวลาสร้างเคสในหน้ารายงาน ต้องยังไม่เกิน 30 วินาที
4. **เจ้าของผลิตภัณฑ์ (Product Owner) ฝั่งบริษัทอนุมัติเป็นลายลักษณ์อักษร** แนบผลข้อ 3
5. จึงแก้ `REQUIRED_CAPTURE_FIELDS`, ตัวตรวจใน backend, ฟอร์ม และเทสต์ ใน PR เดียวที่อ้างอิงการอนุมัติ
