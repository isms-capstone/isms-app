# คู่มือทดสอบ SEA, ATT และ AUD

Branch: `SEA-01-03+ATT-01-04+AUD-01-03`

ขอบเขตรอบนี้คือ SEA-01–03, ATT-01/02/04 และ AUD-01/02 ตาม PRD ส่วน ATT-03 และ AUD-03 อยู่นอกขอบเขตรอบนี้ ชื่อ branch ครอบคลุมรหัสตามที่ทีมกำหนด

## เตรียมระบบ

1. ใช้ backend และ frontend จาก branch นี้ ฐานข้อมูลทดสอบต้องผ่าน `alembic upgrade head` ถึง `sea01_case_search` การ migration สร้างดัชนีจากหัวข้อ รายละเอียด และ worklog ของเคสเดิมด้วย
2. เปิด MariaDB, MinIO และ API ตาม [วิธีรัน backend](../README.md) ในขั้นเริ่มบริการให้เปิด MinIO ด้วย `docker compose up -d minio` และใช้ค่าตั้ง MinIO คู่เดียวกันระหว่าง API กับบริการจัดเก็บไฟล์
3. เปิด frontend ตาม [วิธีรัน Next.js](../frontend/README.md) แล้วเข้า `http://localhost:3100/login` ด้วยบัญชี Admin สำหรับทดสอบ เตรียมบัญชีสมาชิกทีมเดียวกัน บัญชีต่างทีม และ Agent ที่ไม่ได้เกี่ยวข้องกับเคสไว้ตรวจสิทธิ์
4. เลือกลูกค้าที่ผูกผลิตภัณฑ์ไว้แล้วและเตรียมเคสทดสอบสองรายการที่มีค่าต่างกันอย่างน้อยหนึ่งตัวกรอง หากรายการค้นหาว่าง ให้สร้างเคสในระบบทดสอบก่อน ตัวกรองลูกค้า ผลิตภัณฑ์ และผู้รับผิดชอบแสดงจากเคสที่บัญชีมีสิทธิ์เห็น

## SEA-01 ค้นหาภาษาไทยติดกัน

1. สร้างเคสทดสอบหนึ่งเคส ใส่หัวข้อ `หน้าจอค้างตอนเข้าสอบ` และรายละเอียด `ส่งข้อสอบไม่ได้หลังยืนยันคำตอบ`
2. เปิดรายละเอียดเคส ในไทม์ไลน์เพิ่ม Internal Note ที่มีข้อความ `ตรวจพบว่าเข้าสู่ระบบไม่ได้`
3. เปิดเมนู **ค้นหาเคส** ที่ `/cases/search` ค้นทีละคำ ได้แก่ `หน้าจอค้าง`, `ส่งข้อสอบไม่ได้`, `เข้าสู่ระบบไม่ได้` และเลขเคส กด **ค้นหา** ทุกครั้ง เคสทดสอบต้องอยู่ในผลลัพธ์และกดเปิดเคสได้
4. ลองคำที่ไม่มีในเคสและตรวจข้อความ **ไม่พบเคสที่ตรงกับเงื่อนไข** บทความ KB อยู่ใน Phase 5 ตาม PRD

## SEA-02 ตัวกรองและมุมมอง

1. ในหน้าเดียวกัน เลือกสถานะ ลูกค้า ผลิตภัณฑ์ ผู้รับผิดชอบ วันรับแจ้งตั้งแต่–ถึง และ Severity ให้ตรงกับเคสที่เตรียมไว้ กด **ค้นหา** ผลต้องตรงทุกเงื่อนไข ลองเปลี่ยนเงื่อนไขหนึ่งให้ไม่ตรงและตรวจว่าเคสหลุดจากผล
2. กรอกชื่อ `เคสสอบของฉัน` เลือก **ส่วนตัว** แล้วกด **บันทึกมุมมอง** รีเฟรชหน้าและกดชื่อมุมมอง ตรวจว่าคำค้นและตัวกรองกลับมาครบพร้อมผลค้นหา
3. ใช้บัญชีที่มีทีม สร้างมุมมอง **ทีมของฉัน** แล้วเข้าอีกบัญชีในทีมเดียวกัน ต้องเปิดมุมมองทีมได้แต่ไม่เห็นมุมมองส่วนตัว บัญชีต่างทีมต้องไม่เห็นมุมมองทีม ผลค้นหาของแต่ละบัญชียังขึ้นกับสิทธิ์ของบัญชีนั้น

## SEA-03 CSV และ Excel

1. ใช้ Admin, Team Lead หรือ Executive ค้นหาและกด **ส่งออก CSV** กับ **ส่งออก Excel** เปิด `cases.csv` และ `cases.xlsx` ตรวจเลขเคส หัวข้อภาษาไทย สถานะ Severity และจำนวนแถวเทียบกับผลค้นหาทุกหน้า
2. เปลี่ยนตัวกรองแล้วกดค้นหาใหม่ก่อนส่งออก ตรวจว่าไฟล์สะท้อนผลที่เพิ่งค้นหา
3. เข้าเป็น Agent ตรวจว่าปุ่มส่งออกไม่ปรากฏ ชุดทดสอบ API ตรวจการปฏิเสธการส่งออกและตรวจบันทึกผู้ส่งออก เวลา รูปแบบ ตัวกรอง และ ID เคสใน `case_export_audit` การดูประวัติส่งออกตรวจจากฐานข้อมูลหรือชุดทดสอบ API

## ATT-01 อัปโหลดไฟล์และตรวจขนาด

1. เปิด **สร้างเคส** ขยายส่วนแนบไฟล์ กด **เลือกไฟล์** เลือกไฟล์ตัวอย่าง PNG, PDF, MP4/WebM และ ZIP ที่มีไฟล์ .log หรือ .txt แล้วสร้างเคส ตรวจว่ารายชื่อไฟล์แสดงในเคสที่เปิดขึ้น
2. ลองไฟล์เกิน 25 MiB, ไฟล์ชนิดที่ไม่รองรับ และไฟล์ที่เปลี่ยนนามสกุลเป็น PNG โดยเนื้อหายังเป็นข้อความ ตรวจว่าระบบแจ้งข้อผิดพลาดและไฟล์ที่ถูกปฏิเสธไม่ปรากฏในไทม์ไลน์
3. ถ้าสร้างเคสสำเร็จแต่อัปโหลดสะดุด ให้แก้รายการไฟล์แล้วกดบันทึกซ้ำ ระบบแนบไฟล์ที่เหลือกับเคสเดิม ตรวจว่ามีเคสเดียวและไฟล์ที่สำเร็จแล้วไม่ซ้ำ

## ATT-02 ภาพย่อและภาพเต็ม

1. เปิดเคสที่แนบ PNG แล้วเลื่อนไป **ไทม์ไลน์รวม** หาเหตุการณ์ **แนบไฟล์** ต้องเห็นภาพย่อ
2. คลิกภาพ ภาพเต็มต้องเปิดในกล่องบนหน้าเดิมโดยไม่มีการดาวน์โหลด กด **ปิดภาพ** แล้วตรวจว่ายังอยู่ที่เคสเดิม

## ATT-04 สิทธิ์และวันหมดอายุของลิงก์

1. บัญชีที่มีสิทธิ์เปิดเคส กดชื่อไฟล์เพื่อดาวน์โหลด ตรวจว่าเนื้อหาและชื่อไฟล์ตรงกับต้นฉบับ
2. คัดลอกลิงก์ดาวน์โหลดไปเปิดในหน้าต่างส่วนตัวที่ยังไม่เข้าสู่ระบบ แล้วลองอีกครั้งด้วยบัญชี Agent ที่ไม่ได้เกี่ยวข้องกับเคส ทั้งสองกรณีต้องไม่ได้รับไฟล์
3. ลิงก์มีอายุหนึ่งชั่วโมงและผูกกับผู้ใช้และไฟล์ หากต้องการตรวจบน UI ให้เก็บลิงก์เดิมไว้แล้วลองหลังหมดอายุ จากนั้นเปิดเคสใหม่เพื่อรับลิงก์ใหม่ ชุดทดสอบ API ตรวจการหมดอายุได้ทันทีด้วยลิงก์ที่กำหนดเวลาหมดอายุไว้แล้ว

## AUD-01 ประวัติการเปลี่ยนฟิลด์

1. เปิดเคสทดสอบ เปลี่ยน Severity หรือประเภทปัญหาแล้วบันทึกหมวดหมู่ หากปรับ Severity ต่างจากค่าที่เสนอ ให้กรอกเหตุผลตามขั้นตอน CAT เดิม
2. ใน **ไทม์ไลน์รวม** หา **เปลี่ยนข้อมูลสำคัญของเคส** แล้วกด **ค่าเดิม / ค่าใหม่** ตรวจผู้ดำเนินการ เวลา และค่าเก่า/ใหม่
3. ทำซ้ำกับการมอบหมายงานหรือเปลี่ยนสถานะที่บัญชีมีสิทธิ์ทำ แล้วรีเฟรชเพื่อยืนยันว่าประวัติยังอยู่ Backend ตรวจฟิลด์ `status`, `severity`, `owner_id`, `assignee_id`, `category_id` เมื่อมีการเปลี่ยนจริง

## AUD-02 ยกเลิกโดยเก็บเคสไว้

1. เข้า Admin เปิดเคสทดสอบสถานะ New ไปที่ **การดำเนินการกับเคส** แล้วกด **ยกเลิกเคส (สร้างผิด)**
2. ลองยืนยันโดยเว้นเหตุผลว่าง ระบบต้องไม่เปลี่ยนสถานะ จากนั้นกรอก `เคสทดสอบซ้ำ` และกด **ยืนยันเปลี่ยนสถานะ**
3. สถานะต้องเปลี่ยนเป็น `CANCELLED` เปิด URL เคสเดิมอีกครั้งและตรวจว่าเคสกับไทม์ไลน์ยังอยู่ หรือค้นเลขเคสด้วยตัวกรองสถานะ CANCELLED ชุดทดสอบ API ตรวจว่าไม่มีการลบเคสถาวรผ่าน endpoint และตรวจการปฏิเสธคำสั่งลบจาก ORM ด้วย
